# ספריית תבניות לפי סוג נכס

מבנה מוכן לכל סוג נכס. הסוכן בוחר את התבנית לפי סוג הבקשה, ממלא את השלד, ומתאים לטון המותג. **תבנית = נקודת פתיחה, לא כלוב.**

עקרונות רוחביים לכל התבניות:
- **תועלת לפני תכונה.** מה זה נותן ללקוח, ואז מה זה.
- **פעולה אחת ברורה** לכל נכס (CTA יחיד עיקרי).
- **מובייל-first**, הדבר החשוב בקיפול העליון.
- **קול פעיל, משפטים קצרים, ללא ז'רגון מיותר.** (ראה `common-mistakes.md`)

---

## 1. Hero Section (ראש דף)

```
[כותרת ראשית]  : התועלת/הטרנספורמציה במשפט אחד. לא שם המוצר.
[תת-כותרת]     : למי זה, איך זה עובד, ומה מייחד. 1–2 שורות.
[CTA ראשי]     : פועל + תועלת. ("התחילו בחינם", לא "שליחה")
[CTA משני]     : אופציונלי, low-commitment ("צפו בדמו")
[הוכחה מהירה]  : שורת אמון: לוגואים / מספר משתמשים / דירוג
```
**כללים:** הכותרת עונה על "מה יוצא לי מזה?" תוך 5 שניות. אם אפשר לקרוא את הכותרת ולא לדעת מה המוצר עושה, היא כללית מדי.

**דוגמה (SaaS ל-HR):**
> **כותרת:** גיוס עובדים בחצי מהזמן, בלי גיליונות אקסל
> **תת:** פלטפורמה שמרכזת מועמדים, ראיונות והחלטות במקום אחד. מתאים לצוותי HR של 5–50 עובדים.
> **CTA:** התחילו ניסיון של 14 יום · **משני:** צפו בסיור מוצר (2 דק')

## 2. FAQ (שאלות נפוצות)

```
לכל שאלה:
[שאלה]  : בשפת הלקוח, כפי שהוא באמת שואל (לא כפי שהחברה מנסחת)
[תשובה] : תשובה ישירה במשפט הראשון, ואז פירוט קצר. מסתיים בהרגעה/CTA עדין.
```
**כללים:** ה-FAQ הוא כלי טיפול בהתנגדויות, לא רק מידע טכני. סדר את השאלות לפי מה שחוסם קנייה (מחיר, ביטול, אבטחה, זמן הטמעה). שאב ישירות מקטגוריה 7 ב-`discovery-questions.md`.

**מבנה שאלות מומלץ:** מחיר/ביטול ← כמה זמן לוקח ← למי זה מתאים/לא מתאים ← אבטחה/פרטיות ← תמיכה ← "במה אתם שונים מ___".

## 3. Pricing (דף/סקשן תמחור)

```
[כותרת]        : ממקדת בערך, לא במחיר ("בחרו את התוכנית שגדלה איתכם")
לכל חבילה:
  [שם החבילה]  : מתאר קהל, לא גודל ("לצוותים קטנים", לא "Basic")
  [מחיר + מסגור],  חודשי/שנתי, חיסכון מודגש
  [שורת ערך]   : למי זה מתאים במשפט
  [רשימת תכונות],  תועלת קודם, מסומן מה שכלול
  [CTA]        : אחיד בין החבילות
[הסרת סיכון]  : "בטלו בכל עת", "החזר כספי 30 יום"
[FAQ תמחור קצר],  3–4 שאלות: חיוב, שדרוג, ביטול
```
**כללים:** הדגש חבילה מומלצת ("הכי פופולרי"). ענה על התנגדות המחיר במקום (שאלות 18–19 ב-discovery). לעולם אל תשאיר את המחיר "עירום" בלי הקשר של ערך.

## 4. CTA (קריאה לפעולה)

```
[טקסט כפתור] : פועל בגוף ראשון/ציווי + תועלת. 2–4 מילים.
[מיקרו-קופי] : מתחת/ליד: מסיר חיכוך ("ללא כרטיס אשראי", "לוקח 30 שניות")
```
**נוסחת כפתור:** *פועל + תוצאה.* "קבלו את המדריך" > "שליחה". "התחילו לחסוך" > "המשך".
**להימנע מ:** "לחצו כאן", "שלח", "הרשמה" יבש, "למד עוד" כברירת מחדל.
**טיפ:** נסח את הכפתור כהשלמה של "אני רוצה ל___".

---

## 5. דף מוצר (Product Page)

```
[כותרת מוצר]    : תועלת-על, לא רק שם
[תת-כותרת]      : משפט מיצוב
[תמונה + alt טקסט]
[3–5 Benefits]  : כותרת-תועלת + משפט הסבר (מבנה FAB)
[איך זה עובד]   : 3 צעדים פשוטים
[הוכחה חברתית]  : עדות/דירוג/נתון
[טיפול בהתנגדות], משפט שמסיר את החשש העיקרי
[מפרט/פרטים]    : לגולשים ה"רציונליים"
[CTA + הסרת סיכון]
```
**כללים:** כל תכונה מלווה בתועלת. הקדם עדות אחת חזקה לפני המפרט. אם יש השוואה למתחרים, טבלה קצרה עם 3–5 שורות בלבד.

## 6. מיילים (Email)

### מייל מכירה
```
[Subject]    : סקרנות/תועלת, < 50 תווים. (בדוק מול 4 U's)
[Preheader]  : משלים את ה-subject, לא חוזר עליו
[פתיח]       : הוק אישי (PAS: בעיה בשורה הראשונה)
[גוף]        : תועלת אחת מרכזית + הוכחה. פסקאות קצרות.
[CTA]        : לינק/כפתור אחד, חוזר פעם-פעמיים
[P.S.]       : התנגדות/דחיפות/בונוס. (נקרא הרבה, נצל אותו)
```

### מייל Welcome / Onboarding
```
[Subject]    : חם, מאשר ("ברוכים הבאים, הנה איך מתחילים")
[פתיח]       : אישור + מה מקבלים
[צעד ראשון]  : פעולה אחת קטנה שמובילה ל-"רגע אהה"
[CTA יחיד]   : לפעולה הראשונה במוצר
[עזרה]       : לאן לפנות
```

### מייל Nurture / חינוכי
מסגרת QUEST. ערך תחילה, מכירה עדינה בסוף. בלי לחץ.

**כללים כלליים למייל:** subject ו-CTA הם 80% מההצלחה. רעיון אחד למייל. כתוב כמו אדם, לא כמו חברה.

## 7. Onboarding (מיקרו-קופי במוצר)

```
[מסך פתיחה]     : תועלת + מה עומד לקרות. לא "ברוך הבא" ריק.
[הסבר צעד]      : משפט אחד לכל צעד. אומר מה לעשות ולמה.
[Tooltips]      : נקודתי, רק כשצריך. פועל + תוצאה.
[Progress]      : "שלב 2 מתוך 3", נותן תחושת התקדמות
[Empty-first]   : המסך הראשון הריק: מזמין לפעולה הראשונה
[Success state] : חיזוק חיובי ברגע ההצלחה הראשונה
```
**כללים:** טון מעודד ומכוון-פעולה. כל מסך = צעד אחד. הסר חרדה, תן ניצחון מהיר. אל תסביר תכונות, הובל לפעולה.

---

## 8. הודעות שגיאה (Error Messages)

```
[מה קרה]     : בשפה אנושית, לא קוד. בלי להאשים את המשתמש.
[למה / הקשר] : קצר, אם עוזר
[מה לעשות]   : הצעד הבא הברור. תמיד תן מוצא.
```
**נוסחה:** *בעיה נטרלית + פתרון פעיל.*
- ❌ "שגיאה: קלט לא תקין"
- ✅ "כמעט, נראה שהאימייל חסר @. בדקו ונסו שוב."
**כללים:** בלי האשמה ("אתה הזנת..."), בלי דרמה, בלי ז'רגון. תמיד עם מוצא. במצב חמור, טון מרגיע + איך ליצור קשר.

---

## 9. Empty States (מצבים ריקים)

```
[כותרת]   : מסגרת חיובית, לא "אין כלום"
[משפט]    : מה אפשר לעשות כאן
[CTA]     : הפעולה הראשונה שממלאת את המסך
[איור/רמז], אופציונלי, מפחית "קור"
```
**סוגי Empty State:**
- **ראשוני** (עוד לא התחיל) ← הזמנה + הדרכה. "עדיין אין פרויקטים. צרו את הראשון."
- **הושלם** (סיים הכל) ← חיזוק חיובי. "כל המשימות סגורות. כל הכבוד 🎉"
- **תוצאות חיפוש ריקות** ← הצע חלופה. "לא מצאנו התאמה ל'X'. נסו מונח אחר."
**כללים:** empty state הוא הזדמנות, לא כישלון. הפוך ריקנות לצעד הבא.

## 10. Push Notifications

```
[כותרת] : < 40 תווים. ערך מיידי / סקרנות.
[גוף]   : < 100 תווים. סיבה אחת לפתוח עכשיו.
```
**כללים:** חיובי ומעודד, לא נודניק. ערך לפני בקשה. פרסונליזציה כשאפשר. תזמון > תדירות. בלי CAPS, בלי לחץ מזויף.
- ✅ "3 דקות זמן פנוי? סיימת היום נשימה קצרה 🌿"
- ❌ "אתה לא נכנס כבר 3 ימים!!!"

## 11. תבניות נוספות (מבנה מקוצר)

- **Testimonial framing:** [תוצאה מדידה] + [ציטוט אנושי] + [שם, תפקיד, חברה]. הכי חזק פותח בתוצאה.
- **About / אודות:** StoryBrand, הלקוח גיבור, אתם המדריך. סיפור "למה", לא רק "מה".
- **Coming soon / Waitlist:** תועלת + בלעדיות + CTA להרשמה + מה מקבלים בתמורה.
- **Banner מבצע:** הצעה + דחיפות אמיתית + CTA. משפט אחד.
- **404:** קליל + מוצא ("הדף ברח. בואו נחזיר אתכם הביתה ←").
- **Confirmation / Success:** אישור ברור + מה קורה עכשיו + צעד הבא.
- **Unsubscribe / ביטול:** מכובד, בלי אשמה, עם דלת פתוחה לחזרה.

> לכל תבנית: מלא לפי הבריף, בחר framework מ-`frameworks.md`, ואז העבר דרך `qa-rubric.md` לפני שליחה.
