# מאגר הידע של סוכן הקופי

התיקייה הזו הופכת את הסוכן מ"כותב טקסט" ל"קופירייטר בכיר שמנהל לקוח". היא מכילה חמישה מאגרי ידע שהסוכן טוען לפי הצורך.

## הקבצים

| קובץ | מתי הסוכן משתמש בו |
|------|--------------------|
| `discovery-questions.md` | **כשחסר מידע חוסם.** מאגר לשליפה: בוחרים ממנו את השאלה הנכונה. כמה לשאול נקבע בהנחיות המערכת (משימה גדולה: עד חמש, אחת בכל הודעה). |
| `frameworks.md` | **לפני כתיבת כל נכס.** לבחור מסגרת שיווקית לפי מודעות הקהל והפורמט, לא להשתמש תמיד באותה שיטה. |
| `templates.md` | **בזמן הכתיבה.** מבנה מוכן לכל סוג נכס: Hero, FAQ, Pricing, CTA, מיילים, Onboarding, שגיאות, Empty States, Push. |
| `common-mistakes.md` | **בזמן הכתיבה ובבקרה.** רשימת דפוסים לזיהוי-עצמי + התיקון לכל אחד. |
| `qa-rubric.md` | **לפני שליחת כל תשובה.** הסוכן מדרג את עצמו מול קריטריונים קבועים; אם קריטריון נופל מהסף, משכתב לפני שליחה. |

## תהליך העבודה המומלץ של הסוכן

```
1. בירור      · discovery-questions.md   (רק מה שחסר וחוסם)
2. אסטרטגיה  · frameworks.md            (בחר framework מתאים לקהל+פורמט)
3. כתיבה      · templates.md             (מלא את התבנית של סוג הנכס)
4. ביקורת     · common-mistakes.md       (סרוק לדפוסים בעייתיים ותקן)
5. בקרת איכות · qa-rubric.md             (דרג, ואם נכשל, שכתב וחזור על 5)
6. שליחה     · רק תשובה שעברה את הסף
```

**כשיש סתירה בין קובץ ידע להנחיות המערכת, ההנחיות גוברות.**

## עקרונות-על

- **לשאול פחות, לשאול חכם.** אם המידע כבר קיים בבריף/בהקשר, לא לשאול עליו שוב.
- **מסגרת מתאימה > מסגרת מוכרת.** אין framework אחד שמנצח תמיד; הבחירה תלויה במודעות הקהל ובערוץ.
- **בקרה לפני שליחה, לא אחריה.** כל טיוטה עוברת את `qa-rubric.md` בשקט, והמשתמש רואה רק את התוצר שעבר.

## איך לתחזק

כל מאגר הוא רשימה שאפשר להרחיב. כשמזהים שאלה טובה, framework חדש, טעות חוזרת או קריטריון איכות, מוסיפים לקובץ המתאים. הסוכן ישתפר ככל שהמאגרים גדלים.
