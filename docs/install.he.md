# התקנה ושימוש

כל סקיל הוא תיקייה עם קובץ אחד, `SKILL.md`. יש שלוש דרכים להשתמש בו, מהפשוטה למלאה.

## 1. בלי התקנה: העתקה לשיחה

פותחים את ה-`SKILL.md`, מעתיקים את התוכן שמתחת לכותרת, ומדביקים בתחילת שיחה בכל צ'אט AI. מתאים לניסיון חד פעמי.

## 2. ב-claude.ai: פרויקט לכל סוכן

1. פותחים Project חדש.
2. מדביקים את תוכן ה-`SKILL.md` בשדה ההנחיות של הפרויקט (Instructions).
3. כל שיחה חדשה בפרויקט מתחילה עם ההנחיות האלה, בלי להדביק שוב.

כללי כתיבה (`human-writing-he`, `site-copy-he`) אפשר לשים גם בהנחיות הכלליות של החשבון, ואז הם חלים על כל שיחה.

## 3. ב-Claude Code: סקיל מותקן

מעתיקים את תיקיית הסקיל לאחד משני מקומות:

- `~/.claude/skills/` כדי שיהיה זמין בכל הפרויקטים.
- `.claude/skills/` בתוך פרויקט, כדי שיהיה זמין רק בו.

```bash
git clone https://github.com/kai12342026/Kopel.AI.git
```

```bash
cp -r Kopel.AI/skills/human-writing-he ~/.claude/skills/
```

Claude טוען את הסקיל לבד כשהבקשה מתאימה לתיאור שלו. סקיל כמו `save` אפשר גם להפעיל ביד, עם `/save`.

## לפני שמתקינים סקיל, מכל מקור

סקיל הוא הוראות ש-Claude יבצע בשמכם. זה נכון גם לסקילים שכאן.

1. קוראים את `SKILL.md` עד הסוף.
2. בודקים מי פרסם, כמה משתמשים בו ומתי עודכן.
3. מחפשים פקודות שמורידות ומריצות קוד מהרשת, או ששולחות מידע החוצה.
4. מתקינים קודם בפרויקט ניסיון, לא בפרויקט עם לקוחות.
5. לא נותנים לסקיל גישה למפתחות, לסיסמאות או לקובצי `.env`, ולא מכבים את בקשות האישור.

הסקילים בריפו הזה הם קובצי טקסט. אין בהם סקריפטים שרצים, והם לא מורידים דבר. ל-`sticky-scroll-steps` מצורף רכיב React, שמעתיקים לפרויקט רק אם רוצים.
