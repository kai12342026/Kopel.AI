# Sticky Scroll Steps

סקשן "איך זה עובד" שבו הגלילה עצמה היא הניווט. הרפרנס הוא הסקשן "How Jobgether works" ב-jobgether.com.
בגלילה, השלב שנמצא ברצועת הפוקוס במרכז המסך הופך לפעיל, והפאנל בצד נשאר במקום ומחליף את הדמו שבתוכו.

## הכלל הראשון: הצבעים והפונטים של הפרויקט, לא של הרפרנס

בכל פרויקט חדש **ממפים את הטוקנים לצבעי המותג ולפונטים של אותו פרויקט**. לא מעתיקים את הירוק של jobgether
ולא שום ערך hex מהרפרנס. הרכיב קורא רק משתני CSS, והמיפוי נכתב פעם אחת ב-CSS הגלובלי של הפרויקט.
אם לפרויקט אין עדיין פלטה, מציעים פלטה למשתמש ומחכים לאישור לפני שמקבעים אותה.

| טוקן | תפקיד | מה לבדוק |
|---|---|---|
| `--sss-accent` | eyebrow, אייקון, קישור | עובר AA כטקסט על רקע הסקשן (4.5:1) |
| `--sss-bar` | הפס של השלב הפעיל (ברירת מחדל: `--sss-accent`) | לפחות 3:1 מול הרקע |
| `--sss-brand-dark` | כותרת השלב | צבע הכותרות של הפרויקט |
| `--sss-muted` | תיאור השלב | צבע גוף הטקסט של הפרויקט |
| `--sss-divider` | קו מפריד 1px בין שלבים | נראה על רקע הסקשן |
| `--sss-card` | כרטיס ה"מוצר" הלבן | בדרך כלל `--card` |
| `--sss-panel-from` · `--sss-panel-via` · `--sss-panel-to` | גרדיאנט אלכסוני של הפאנל | primary ב-15% ← accent ב-12% ← primary ב-8%, דרך `color-mix` |
| `--site-header-h` | גובה ההדר הדביק, לחישוב `top` של הפאנל | למדוד בדפדפן, כולל פס עליון אם יש |

השמות מקבלים קידומת `sss-` בכוונה: `--accent` ו-`--muted` כבר תפוסים אצל shadcn.
טוקן שנשכח נופל ל-`currentColor` או `Canvas`, כך שהסקשן ייראה מונוכרומטי ולא שבור.

```css
:root {
  --sss-accent: var(--brand-text-accent);
  --sss-brand-dark: var(--heading);
  --sss-muted: var(--body);
  --sss-divider: var(--border);
  --sss-card: var(--card);
  --sss-panel-from: color-mix(in oklch, var(--primary) 15%, transparent);
  --sss-panel-via: color-mix(in oklch, var(--secondary-brand) 12%, transparent);
  --sss-panel-to: color-mix(in oklch, var(--primary) 8%, transparent);
  --site-header-h: 4.5rem;
}
```

גם הטיפוגרפיה עוברת דרך הפרויקט: `classNames` מאפשר להחליף את גודל הכותרת, את מחלקת הגוף ואת סגנון ה-eyebrow
בסקאלה הקיימת. בעברית `uppercase` לא עושה כלום. אם לפרויקט יש מוסכמת eyebrow (למשל בלי uppercase), הולכים לפיה.

## שפת העיצוב

**לייאאוט.** כותרת סקשן, ומתחתיה גריד של שתי עמודות בדסקטופ (`lg:grid-cols-2`, רווח 64px).
- עמודה A (טקסט): רשימה אנכית של שלבים. כל שלב עם ריפוד אנכי של 48px וקו עליון דק בצבע `--sss-divider`.
- עמודה B (דמו): פאנל `sticky` עם `top` של גובה ההדר ועוד 24px. גובה 750px, אבל אף פעם לא יותר מהמסך
  (`min(750px, 100svh - top - 24px)`). פינות `rounded-2xl` וגרדיאנט אלכסוני רך בגווני המותג.
  בתוכו כרטיס לבן (`rounded-xl`, `shadow-2xl`) במרחק 16px מהשוליים ו-40px מלמעלה, ובו הדמו של השלב הפעיל.

**אנטומיה של שלב.** אייקון קטן עם eyebrow ("שלב 1", בערך 12.8px, משקל 600, ריווח אותיות קל, בצבע ה-accent),
כותרת (בערך 20px, bold), פסקה קצרה בצבע הגוף, וקישור טקסט עם חץ.
החץ מתהפך לבד ב-RTL (`rtl:-scale-x-100`), כך שבעברית הוא מצביע שמאלה.

**מצבים.**
- שלב פעיל: `opacity: 1`, פס של 4px בצד ה-inline-start (`border-s-4`) וריפוד `ps-6`.
- שלב לא פעיל: `opacity: 0.4`, בלי פס. ריחוף מעלה ל-0.7, ופוקוס מקלדת מעלה ל-1.
- כל מעבר: `transition-all duration-500 ease-in-out`.
- הדמואים מוערמים ב-`absolute` בתוך הכרטיס. הפעיל ב-`opacity-100`, השאר ב-`opacity-0` עם הזזה של 10px למטה,
  `aria-hidden` ו-`inert`.

## המנגנון

- **IntersectionObserver ולא האזנה ל-scroll.** `rootMargin: "-45% 0px -45% 0px"` יוצר רצועת פוקוס ב-45% עד 55% מגובה המסך.
  כשכמה שלבים נוגעים ברצועה, נבחר זה שהקופסה שלו הכי קרובה למרכז.
- **קצוות.** בטעינה השלב הראשון פעיל. כשאף שלב לא ברצועה: מעל הרשימה נשאר הראשון, מתחתיה נשאר האחרון.
  זה מכסה גם טעינה באמצע הדף.
- **ריצת סיום.** לרשימה יש `padding-bottom` בדסקטופ: הקצה התחתון של הפאנל (top ועוד הגובה) פחות מרכז המסך, פחות 6rem. בלי זה הפאנל משתחרר לפני
  שהשלב האחרון מגיע למרכז המסך, והקרוספייד האחרון קורה כשהפאנל כבר בורח מהמסך. ב-jobgether עצמו הבעיה הזו קיימת:
  שלושה שלבים של 890px מול פאנל של 750px.
- **לחיצה.** לחיצה על שלב מפעילה אותו וגוללת אליו ל-`block: "center"`. בזמן הגלילה המתוכנתת עדכוני ה-observer מושהים,
  כדי שהשלבים שבדרך לא יהבהבו. הנעילה משתחררת ב-`scrollend` או אחרי 1.2 שניות. קליק על הקישור שבתוך השלב לא נחטף.
- **מקלדת.** הכותרת של כל שלב היא `<button>` נייטיב: Tab מגיע אליו, ו-Enter או Space מפעילים. אין `role="button"`
  על ה-`li`, כי בתוכו יש קישור, ואלמנט אינטראקטיבי בתוך כפתור הוא הפרת נגישות.
- **`aria-current="step"`** על השלב הפעיל, ו-`aria-controls` מהכפתור לדמו שלו.
- **reduced motion.** בלי הזזה, opacity מיידי, וגלילה ב-`instant`.
- **מובייל (מתחת ל-`lg`).** אין sticky ואין מצב פעיל. כל שלב מוצג באטימות מלאה, והדמו שלו בכרטיס ממש מתחתיו
  עם fade-in עדין בכניסה למסך. מצב ההסתרה מוחל רק אחרי mount, כך שבלי JS הדמו גלוי. אף פעם לא מסתירים דמו במובייל.

## ה-API

```tsx
<StickyScrollSteps
  heading?: ReactNode          // אם יש, הרכיב מרנדר <section aria-labelledby>
  subheading?: ReactNode
  steps={[{
    id: string,
    eyebrow: string,           // "שלב 1"
    title: string,
    description: ReactNode,
    icon?: ReactNode,          // aria-hidden
    link?: { label: string, href: string },
    demo: ReactNode,           // UI מיני ב-JSX
  }]}
  stickyTop?: string           // ברירת מחדל: calc(var(--site-header-h, 4.5rem) + 1.5rem)
  panelHeight?: string         // ברירת מחדל: 46.875rem (750px)
  panelClassName?: string
  className?: string
  classNames?: { heading, subheading, list, step, eyebrow, title, description, link, card, mobilePanel }
  inactiveOpacity?: number     // ברירת מחדל: 0.4
  focusBand?: string           // ברירת מחדל: "-45% 0px -45% 0px"
/>
```

`useStepActive()` מחזיר `true` כשהדמו מוצג (תמיד `true` במובייל). כך דמו יכול להפעיל אנימציה רק כשרואים אותו:
וי שנכנס, פס התקדמות שמתמלא.

## איך משתמשים בפרויקט חדש

1. **לקרוא את הפרויקט:** גרסת Tailwind (v3 עם config או v4 עם `@theme`), טוקני צבע, פונטים, מנגנון i18n,
   והאם Framer Motion כבר מותקן. אם כן, מותר להשתמש בו לקרוספייד. אם לא, לא מתקינים.
2. **להעתיק** את `templates/StickyScrollSteps.tsx` לתיקיית הרכיבים. הרכיב צריך פונקציית `cn`
   (clsx + tailwind-merge) בקובץ ה-utils של הפרויקט, כמו בכל פרויקט shadcn. אם אין, ליצור.
3. **למפות טוקנים** ב-CSS הגלובלי (טבלה למעלה), ולמדוד את גובה ההדר בדפדפן.
4. **לבדוק אב עם overflow.** `position: sticky` נשבר בשקט כשלאחד האבות יש `overflow: hidden` או `auto`.
   אם צריך לחתוך גלישה אופקית, `overflow-x: clip` לא שובר sticky.
5. **טקסטים מה-i18n.** אין מחרוזת קשיחה בקומפוננטה. קופי פלייסהולדר מסומן בהערה ברורה ונרשם ב-TODO.
6. **דמואים ב-JSX:** צ'קליסט, כרטיס התקדמות, טיימליין קטן. בלי תמונות. כל דמו בנוי כ-`flex h-full flex-col`
   כדי למלא את הכרטיס בגובה הקבוע בדסקטופ, ולגדול בטבעיות במובייל.
7. **לאמת בדפדפן** (רשימה בסוף).

דוגמה מלאה עם שלושה שלבים: `templates/example-usage.tsx`.

## כן / לא

**כן**
- תכונות לוגיות בלבד: `ps-`, `pe-`, `border-s`, `start-`, `end-`, `text-start`. הפאנל נוחת בצד ה-inline-end לבד.
- `dir` על `<html>` לפי השפה. הרכיב לא מחליט על כיוון.
- טוקנים של הפרויקט, ובדיקת ניגודיות של ה-accent כטקסט.
- דמואים קלים: הם מרונדרים פעמיים ב-DOM (עותק מובייל ועותק פאנל, ואחד מהם תמיד `display: none`).
- `useStepActive` לכל אנימציה בתוך דמו.

**לא**
- לא `left` ולא `right`, לא `ml-` / `mr-` / `pl-` / `pr-`.
- לא האזנה לאירוע scroll כדי לקבוע את השלב הפעיל.
- לא ערכי hex בקומפוננטה ולא העתקת הצבעים של הרפרנס.
- לא `id` קבוע בתוך דמו (הוא מופיע פעמיים) ולא וידאו כבד שרץ אוטומטית.
- לא להסתיר דמואים במובייל ולא להפעיל שם sticky.
- לא להתקין ספריית אנימציה רק בשביל הסקשן.
- לא לעטוף את הסקשן ב-`overflow: hidden`.

## בדיקה לפני מסירה

1. דסקטופ בכל שפה (RTL ו-LTR): השלב הפעיל מתחלף בגלילה, הפס בצד ה-inline-start (ימין בעברית, שמאל ב-LTR),
   הפאנל נשאר במקום ומתחלף בקרוספייד, ולחיצה על שלב גוללת אליו ומדליקה אותו.
2. רוחב 375px: שלב ומתחתיו הדמו שלו, שום דבר לא חתוך, ו-`document.documentElement.scrollWidth` שווה ל-`innerWidth`.
3. `prefers-reduced-motion: reduce`: אין הזזה, המעבר מיידי.
4. מקלדת: Tab מגיע לכותרת השלב, Enter מפעיל, טבעת הפוקוס נראית גם על שלב לא פעיל.
5. צילום מסך בכל מצב ובדיקת ניגודיות. בילד ירוק אינו הוכחה.
